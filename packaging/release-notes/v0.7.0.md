# Oxidify 0.7.0

Alternate playback keeps going through sorted playlists and can carry on with Autoplay, and a large batch of fixes and features comes over from Spotifast, the project Oxidify started from.

## Fixed

- **Sorted and filtered playlists keep playing in alternate playback.** Playing a song from a sorted or filtered playlist sent the list to the engine as plain songs, which it fetched from Spotify again. When Spotify rate-limited that request, the queue fell back to the one song clicked and playback stopped when it ended. The queue is now built from the rows already on screen, starts at the right song even past the first 200, and a queue that arrives after the current song has ended moves straight on to the next one.
- **A dropped playback session picks up where it stopped.** It resumes playing instead of coming back paused, and a single-song pickup no longer loops under repeat.
- **Repeat survives a restart.** The mode you chose is applied with every load instead of being reset to off.
- **Queueing an album never drops songs.** Albums queue as ordered songs on this computer and on other devices, and rate-limited additions retry without losing rows.
- **Sign-in is sturdier.** The sign-in and playback ports are claimed before the browser opens, a port already in use says so, and the sign-in listener bounds how long and how much it reads. Local playback retries quietly with the saved approval after a connection failure.
- **Playback recovers from a stalled or changed output** and starts even when no audio device is present yet. Seeking no longer replays stale audio, and the equalizer resets cleanly after a seek.
- **Oversized artwork and skin archives are refused** as they are read.

## Added

- **Autoplay in alternate playback.** When a list ends, Oxidify continues with similar songs. The Autoplay switch now shows in alternate mode too. Songs that found no match are remembered and skipped for the rest of the list.
- **Proxy settings** for system, HTTP and SOCKS5 proxies, with the password kept in an owner-only file. Spotify playback uses HTTP proxies only; with SOCKS5 it connects directly while everything else uses the proxy.
- **Full-window lyrics.** Press F or F11. The cover sits beside the words, alone when a song has none, and Q shows the queue beside them.
- **Settings search** finds a setting by its words.
- **Click a page's cover** to see it large.
- **Release notes** are one click away in Settings, About.
- **Enter in the Add to playlist search** adds to the highlighted playlist; the arrow keys move the highlight.

## Changed

- Playing a song picked from search plays that song on its own, with Autoplay after it.
- Blends show who added each song.
- Spotify playback state is polled less often, and less again while the window is hidden.
- The sung line of lyrics sits higher, loading pages show placeholders instead of a spinner, the system's reduced-motion setting is followed, and times and dates use fixed-width figures.
- Windows keeps the computer awake while music plays and gives the player thread priority.

## Downloads

Windows installers and portable ZIPs are available for x64 and ARM64. The macOS DMG contains a universal app for Apple Silicon and Intel. Linux archives are available for x64 and ARM64. `checksums.txt` lists SHA-256 hashes; the provenance file identifies the source commit and build run.

Automated tests run on Linux, macOS, and Windows. Alternate playback through a sorted 490-song playlist was exercised by hand on Windows against a live free account: songs ended into the next one, Next followed the list, and a song past row 400 started correctly. macOS and Linux were compiled and tested by CI, not driven by hand.

Windows SmartScreen or macOS Gatekeeper may warn about an unsigned download. See the [installation guide](https://master0ffate.github.io/oxidify/download/) for platform instructions.
