# Oxidify 0.8.4

Old account responses and caches no longer affect a newer sign-in. Late token refreshes, sign-in verification and playback approvals are ignored after their session ends. A fresh shared Web API sign-in retires the old playback approval only after verification; startup restore and personal app authorization leave it alone.

Playlists reload when their snapshot changes, even if the count doesn't. Positional edits wait for confirmed rows, and older membership reads can't undo saves or removals. Pending Connect startup keeps the latest audio settings.

Alternate playback stays paused while a playlist loads and keeps manually queued copies, even when the playlist contains the same song. Seeking near the end of a song or during a stalled download works again. Retries respect server cooldowns, and temporary search failures aren't remembered as misses.

Listening history no longer loses newer plays to an older load or clear. Failed clears report an error without discarding history, and a damaged line doesn't hide the other records.

Windows controls use a random Credential Manager secret; macOS controls authenticate local peers. Older direct TCP controls must use the CLI or update their protocol. Now-playing and device snapshots remain public locally.

Draft release assets are rechecked against the successful build before publication. Downloads include seven payloads: Windows x64 and ARM64 installers and ZIPs, a universal macOS DMG, and Linux x64 and ARM64 tarballs, plus checksums and provenance. Windows was tested manually; Linux and macOS coverage is automated CI, not hands-on.
